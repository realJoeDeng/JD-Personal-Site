# Joe Deng Personal Website — Codex Execution Brief

## 0. User Context

The website owner has no coding background and is new to GitHub. Therefore, the implementation should be beginner-friendly, low-risk, and easy to review visually. Avoid requiring the owner to manually edit code. The owner should mainly copy prompts, upload files, click through GitHub/Vercel/Codex interfaces, and review previews.

## 1. Project Goal

Transform an Apple-style product page clone into a premium personal brand website for Joe Deng / Jingyin Deng.

The site should not look like a traditional resume page. It should feel like a product-launch page where Joe’s professional profile is presented as a clear, premium, cinematic personal brand.

Core positioning:

**Research-informed execution. Built for cross-border capital markets.**

Chinese positioning:

**以研究支撑执行，面向跨境资本市场。**

## 2. Design Philosophy

The existing template is inspired by an Apple product page. Preserve the following qualities:

* Minimal top navigation
* Strong hero section
* Large typography
* Premium dark visual tone
* Smooth section transitions
* Card-based highlights
* Cinematic scrolling rhythm
* Clean spacing and polished layout

But remove or replace:

* Apple product names
* Apple trademarks
* Apple copywriting
* Apple product images or videos
* Any content that makes the site look like a direct Apple copy

The result should be Apple-like in quality, but clearly original and personal to Joe.

## 3. Top Navigation Requirement

The top navigation should only contain major section themes. Do not include many miscellaneous links.

Recommended desktop nav:

**Joe Deng | Highlights | Execution | Projects | Life | Contact**

Recommended Chinese nav:

**Joe Deng | 亮点 | 执行 | 项目 | 生活 | 联系**

Important:

* The nav items should scroll to sections on the same homepage.
* Do not put the language switch inside the main navigation.
* Do not include Resume, Skills, Education, Blog, Download CV, LinkedIn, GitHub, etc. in the main top nav for the first version.
* Later, each major section can be expanded into deeper standalone pages.

## 4. Language Switch Requirement

The Chinese/English switch should be a separate utility control placed on the side or edge of the UI, not inside the main navigation bar.

Suggested placements:

* Desktop: right edge of header, visually separated from the nav
* Mobile: upper-right corner near the menu button
* Optional premium style: small floating side control, such as `中 / EN`

The language switch should feel like a utility control, not a navigation item.

7. Keep the top navigation minimal.

## 10. Beginner-Friendly Workflow

The owner should follow this order:

1. Download the step1.dev cloned project as a ZIP.
2. Create a GitHub account if not already done.
3. Create a new GitHub repository.
4. Upload the ZIP contents to the repository through GitHub web UI or GitHub Desktop.
5. Open Codex and connect it to the repository.
6. Paste Prompt 1 and wait for analysis.
7. Review Codex’s explanation.
8. Paste Prompt 2 and let Codex modify the project.
9. Preview changes.
10. Deploy to Vercel if the project is React/Next.js/Vite, or GitHub Pages if it is a simple static website.

## 11. Expansion Plan

Do not build deep pages in Version 1. First, make the homepage strong.

Later expansion routes:

* `/projects` — deeper transaction/project case studies
* `/research` — market research notes
* `/capital-markets` — U.S. IPO / SEC / Nasdaq insights
* `/life` — photography, music, basketball, Go
* `/cv` — formal resume page

The homepage should act as the premium index page. Deeper pages can be added only after the main story is stable.
